I'm a computer science graduate and systems engineer drawn to a single question: what makes a system *actually* trustworthy — not "trust me" trustworthy, but provably, architecturally trustworthy. That question has taken me through secure backend design, API security, and the realities of regulated financial platforms, and it's now pulling me deep into privacy-enhancing technologies and applied cryptography.

The problems I find most interesting live in the gap between "technically encrypted" and "actually private." That's the gap I work in.

---

### Focus

Designing systems where security is the load-bearing wall, not a feature bolted on afterward. In practice that means API security, authentication, and secure communication protocols; applied cryptography and access control that survives contact with real users; and privacy-preserving, resilient design that holds up when things go wrong.

I work mostly in backend and API design with a strong bias toward Linux and infrastructure I can reason about end to end. I'd rather understand one layer deeply than wave at ten.

**Tools:** Rust · Linux · Python · Bash · Docker

---

### Research interests

**Data privacy for cloud-based machine learning in regulated industries** — keeping training data and inference confidential when the compute isn't yours and the regulator is watching.

**Agentic AI governance and control for regulated industries** — making autonomous agents auditable, bounded, and accountable enough to trust in high-stakes environments.

### Currently building
